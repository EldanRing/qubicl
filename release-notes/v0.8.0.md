# Qubicl 0.8.0

Qubicl 0.8 makes computer state easier for agents to inspect and actions easier
to target and verify. Native desktop windows expose bounded accessibility trees,
element references, window-targeted input and optional post-action observations.
Applications support normal close requests so Save/Discard/Cancel dialogs remain
available. Screenshots remain the fallback when an app lacks accessibility data.

Authenticated browser pages can be read and searched with text continuation,
frame/subtree selection and document-bound cursors. Snapshot pagination no longer
skips controls, passive inspection preserves valid refs, and password values stay
out of snapshots. Browser actions recheck ownership between inputs; a takeover
interrupts remaining input and an uncertain result cannot trigger an automatic
retry of an action that may already have executed.

Keyless research adds provider-aware domain, date and language controls with
retrieval metadata and explicit unsupported-filter errors. Workstation includes
GIMP, Inkscape, Blender, FreeCAD and Kdenlive with editable skills. These apps are
bundled only with workstation; other presets keep their application sets.

## Documents and reliability

Office helpers preserve editable chart slides, embedded workbooks and native
tables during copying and structural edits. Spreadsheet references, charts,
validation, local names, pivot caches and rich text follow supported edits.
Array/data-table formulas expose typed metadata and elapsed durations serialize
as signed ISO 8601. Word supports final/original/markup tracked-change reads and
matching accept/reject behavior across document stories, including row changes.
Comment anchors retain tabs and inline objects. PDF flattening removes form
widgets while preserving their appearances; render manifests identify the exact
source and pages. Office rendering keeps charts visible with macros disabled
and untrusted external links blocked.

Preview links survive temporary listener failures and ordinary ownership release;
share rotation closes old connections and broken upstream transfers terminate
clients. HTTP forwarding preserves website cookies, broker query values remain
usable, compressed responses decode correctly and IPv6 literals are handled.

Terminals retain configured environment/proxy values and share managed-task
limits. All runtimes honor long deadlines, retained-output settings and service
queuing. Completed services remain manageable, and stop-all disables restart.
Viewer ownership transitions serialize and reconcile after reconnects. Provider
pipe failures return tool errors without crashing the control service. Failed
skill replacement preserves the original.

## Upgrade and compatibility

Install `qubicl-cli@0.8.0` when the release is available, then run the managed
upgrade for the intended installation. `qubicl upgrade --all` updates the gateway
and its managed computers; upgrading only one computer leaves the gateway
unchanged. Publication does not automatically upgrade any computer. Durable
homes, identities, credentials and running/stopped intent are preserved.

Saved tool and skill allowlists remain authoritative. Enable the new tools for
existing computers explicitly after upgrading; discover them with `qubicl tools NAME`
and use the documented tool-policy commands. Development control protocol
12 carries the new contracts; old published images keep their original identity.

SSH key rotation publishes a complete versioned key generation. Refresh saved SSH
configuration after rotation because IdentityFile selects the new generation.
Changing SSH access preserves a stopped computer's state. Backups/restores retain
software recipes and task/storage/devcontainer/browser policies; pruning counts
only intact verified archives. Repeated installation imports preserve prior
reports and allocate fresh runtime names. Restored browser ownership is checked
from the workload user's filesystem view, including Docker Desktop mounts.

Service inspection includes queued state. Atomic stop-all disables durable
service declarations while retaining ordinary completed-task history. Typed
spreadsheet formulas now expose structured metadata rather than Python object
representations. Cached formula results are not invented or recalculated;
conversion and rendering report their actual fidelity and cache availability.

## Security and artifacts

This release targets the npm CLI, a Linux x64 native archive, and six runtime
images for Linux amd64 and arm64. Checksums, SBOMs, dependency/image scan evidence,
provenance and signed qualification accompany the prepared release. Image
availability does not establish host-platform or third-party-client support.
The release signing public-key fingerprint is
`SHA256:QqMCp3fQfAreVB-d5HT2C1LBvku2hfXIbI4hOIER1RU`.

Upstream npm 12.2.1 still bundles Undici 6.29.0. The three exact, time-limited
review records retained from 0.7 apply to the same npm-private downloader in
0.8. Two findings can terminate npm's native-addon downloader when it contacts
a malicious endpoint; the third requires TLS options that the reviewed downloader
does not use. This accepts limited risk rather than claiming a patched dependency.
The unchanged expiry is November 12, 2026, at 01:36:44 UTC. See the
[scope, evidence and review condition](../security/npm-undici-review-2026-10-28.md).

## Qualification limitations

Focused source checks and local Linux Docker scenarios cover the changed
behavior, including upgrade, authenticated browsing, active takeover, native
inspection, fresh backup restore, service recovery and repeated imports.
Exact-artifact acceptance qualifies the packaged CLI and protocol surfaces;
it does not establish compatibility with every client or host. The following
limitations are recorded explicitly:

- client-conformance: unverified — No fresh third-party-client or live SSH authentication qualification was performed for 0.8.0.
- mobile-conformance: unverified — No physical mobile browser qualification was performed for 0.8.0.
- platform-conformance: unverified — The full host-platform matrix was not exercised; release acceptance targets Linux x64 with Docker Desktop.
- platform:darwin-arm64: unverified — No physical macOS arm64 host qualification was performed for 0.8.0.
- platform:linux-arm64: unverified — Linux arm64 image construction and scanning do not establish native host qualification.
- platform:wsl-x64: unverified — No live WSL host qualification was performed for 0.8.0.
- protocol:dashboard: unverified — Dashboard API and viewer regression checks do not establish a fresh interactive browser UI qualification.
