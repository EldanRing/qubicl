# Qubicl 0.7.0

Qubicl 0.7 makes computers easier to customize and maintain. Python and npm
installations use durable home locations. Saved apt recipes support adding and
removing packages, explicit refresh, named and bulk upgrades, and portable
secret-free manifest export/apply with previews and offline operation.

Stopped computers regain their gateway control networks after gateway or
computer replacement without being started. Desktop applications can launch
from user-installed locations, including executable symlinks and absolute paths.
SSH stdio connections are available through `qubicl connect NAME --ssh user@host`.

Release construction now reuses unchanged runtime images across CLI versions and
refreshes scans per image. Signed qualification records actual checks and gaps;
native targets are selected explicitly. Ordinary source checks are offline and
build once, with coverage, performance and token measurements optional.

## Upgrade and compatibility

Install `qubicl-cli@0.7.0`, then use the managed upgrade commands for installations
you want to update. Upgrades preserve computer identities, durable homes,
credentials and running/stopped intent. Publication alone changes no installation.

Recipe-bearing state, manifests and pending recipe upgrades require the 0.7 CLI;
older manifests remain supported. Curated recipes follow the selected catalog
base. Custom recipe bases remain pinned during bulk upgrades, and other custom
images require individual upgrades. Interrupted bulk upgrades reuse their exact
prepared images; missing or changed images stop recovery instead of rebuilding.

Manifest exports transfer recipes and configuration, not homes, credentials or
image archives. Recipes require an available base and package repositories and
are not package lockfiles. Apply starts declared computers. Explicit refresh
requires network access and cannot be combined with offline operation. Python
ABI changes preserve the previous environment but require reinstalling packages
into the new environment.

## Security and artifacts

Computer images use upstream npm 12.2.1 without modifications to its private
dependency tree. Host isolation, credentials, path checks and executable identity
remain enforced. Development supports compatible npm versions from 10.9.9 through
12.x; the default release pin remains 10.9.9.

This release targets the npm CLI, a Linux x64 native archive, and six runtime
images for Linux amd64 and arm64. Checksums, dependency and vulnerability evidence,
image provenance and signed qualification accompany the release. Image
availability does not establish host-platform or third-party-client support.

## Qualification limitations

Focused source checks and local Docker scenarios cover the changed behavior.
Exact-artifact acceptance exercises the included CLI and protocol surfaces;
it does not establish compatibility with every client or host. The following
qualification gaps are disclosed explicitly:

- client-conformance: unverified — No fresh third-party-client or live SSH authentication qualification was performed for 0.7.0.
- mobile-conformance: unverified — No physical mobile browser qualification was performed for 0.7.0.
- platform-conformance: unverified — The full host-platform matrix was not exercised; release acceptance targets Linux x64 with Docker Desktop.
- platform:darwin-arm64: unverified — No physical macOS arm64 host qualification was performed for 0.7.0.
- platform:linux-arm64: unverified — Linux arm64 image construction and scanning do not establish native host qualification.
- platform:wsl-x64: unverified — No live WSL host qualification was performed for 0.7.0.
- protocol:dashboard: unverified — Dashboard API checks do not establish a fresh interactive browser UI qualification.
