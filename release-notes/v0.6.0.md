# Qubicl 0.6.0

Qubicl 0.6 turns a computer into a practical persistent workspace. Browser,
desktop, task, terminal, preview, networking, credential, backup, recovery, and
dashboard lifetimes now follow the resource being used instead of one global
lease.

## Highlights

- **Normal browser use.** Chromium keeps a durable profile for logins,
  extensions, downloads, and human handoff. Sandbox-friendly launch settings
  replace Playwright testing defaults, tabs have stable IDs, and the visible
  24-tab agent budget fails explicitly rather than discarding old tabs.
- **Work survives disconnects.** Commands default to retained tasks with
  bounded logs and list, wait, input, attach, and stop controls. Declared
  services restart after a runtime restart; arbitrary jobs never replay.
  Interactive PTYs are available to MCP and Open Terminal clients.
- **Ownership matches the action.** Browser, desktop, and PTY input remains
  exclusive and is fenced immediately on takeover. Observation, file work,
  retained tasks, services, and operator SSH continue. Viewer reconnect grace
  is visible, portable through export/apply manifests, and configurable from 5
  to 300 seconds, with a 10-second default.
- **Installed apps work.** Qubicl returns a bounded catalog of safe built-ins
  and user/system desktop entries instead of limiting launch to a product
  whitelist. It preserves resolved executable identity, capacity bounds, safe
  home-relative document paths, and an explicit warning before closing unsaved
  work.
- **Usable app previews and networking.** Preview publications use isolated
  origins, root paths, and normal app cookies. Owner access follows the app;
  remote shares expire independently. Custom egress supports domains, CIDRs,
  and TCP ports, and revocation closes managed tunnels and upgraded connections.
- **Independent client access.** Named client credentials have separate labels,
  scopes, rotation, and revocation. The compatibility token remains available
  for existing integrations.
- **Recovery you can move.** Manual home backups support encrypted dashboard
  create, verify, and restore. Full-installation export, inspect, and import
  moves protected state and every durable home to a fresh stopped installation.
- **Less dashboard friction.** Routine saves are direct. Local login survives a
  same-tab refresh and clears on logout or tab close. Destructive, interrupting,
  and authority-expanding actions still require review or reauthentication.

## Upgrade and compatibility

0.6 uses state format 5 and control protocol 11. Install the matching CLI, make
a complete backup, review the migration, and upgrade the coordinated runtime:

```sh
npm install -g qubicl-cli@0.6.0
qubicl setup
qubicl upgrade --all
qubicl doctor
```

Migration preserves computer and client IDs, names, homes, browser profiles,
credentials, resources, explicit network restrictions, and running/stopped
intent. It does not replay arbitrary tasks. Older CLIs refuse state format 5;
downgrade requires restoring the complete pre-migration installation with a
compatible CLI.

Runtime resource names now include the installation identity, including for
the default state root. Existing 0.5 runtime names are migrated during the
coordinated upgrade, and `gateway` can be used as an ordinary computer name.

Existing default computer tokens still authenticate compatible clients. Create
named credentials when clients should rotate or revoke independently:

```sh
qubicl token create NAME open-webui --label "Open WebUI" \
  --scopes observe,files,tasks,interactive,publish
qubicl token show NAME open-webui
```

## Security changes

Git executes inside the computer rather than against a repository with host
operator authority. Chromium retains its Linux sandboxes and no longer receives
unsafe testing defaults. Public rendered extraction uses a separate anonymous
context without saved browser state. Operator release uses a distinct internal
key, named client credentials have bounded scopes, audit ingestion and rotation
are centralized, and preview/egress revocation closes the connections it owns.

One computer remains a cooperative workspace. Processes and clients inside it
are not hostile-code isolation boundaries. Use separate computers for mutually
untrusted work, and remember that the unrestricted `developer` profile can send
any data available inside that computer.

## Known limitations

- The publisher requires the complete signed six-image candidate even though
  release-impact metadata identifies affected artifacts and reusable evidence.
- Backups remain manually initiated; scheduled backups are outside 0.6.
- Qubicl does not manage remote DNS, certificates, routers, firewalls, tunnels,
  or third-party remote-access services.
- Devcontainer feature plugins, Compose definitions, notebooks, and new platform
  support claims remain outside 0.6.

## Release evidence

The 0.6 candidate embeds `release-impact.json`, binding the exact prior release
commit and candidate commit to changed paths, artifacts, checks, protocols,
platforms, and evidence-reuse rules. Missing required coverage cannot pass.
Release artifacts include the signed candidate, checksums, SBOMs, vulnerability
evidence, release set, acceptance records, and exact image catalog described in
