# Qubicl 0.2.1

Qubicl 0.2.1 corrects file editing, browser references, and Open WebUI folder
behavior, improves bounded search, and adds workstation Office PDF previews.

## Highlights

- Open WebUI's native editor receives complete UTF-8 files up to 20 MB, including
  BOMs and line endings. Larger or unsupported files fail instead of presenting
  a prefix that could overwrite the original on save. Model reads retain their
  separate context budget and correctly report clipped long lines.
- Browser references stay attached to the original DOM nodes when nearby
  controls move. Removed/replaced nodes require a fresh snapshot. Snapshot
  checks overlap with bounded concurrency, and semantic actions no longer
  impose an unconditional 300 ms delay after Playwright completes.
- Open WebUI discovers `run_command` and `replace_file_content` for its native
  folder guidance and refresh events. Relative file paths and omitted command
  working directories follow the folder selected in that chat.
- Search prunes hidden and Git-ignored directories before descending, returns
  useful partial results at limits, and reuses bounded continuation pages.
- Workstation can render DOCX and PPTX previews as PDF using private temporary
  profiles, disabled macros/active content, a sanitized environment, size/time
  and concurrency limits, and cancellation on disconnect or human takeover.
  Original downloads remain unchanged.
- `qubicl audit prune --keep 0` correctly retains zero events. Planning guidance
  respects read-only requests, and enabled skill guidance is distinguished from
  untrusted external tool content.

## Upgrade and compatibility

Install the matching CLI and review the coordinated computer upgrade:

```sh
npm install -g qubicl-cli@0.2.1
qubicl upgrade --all
```

The CLI and runtime images must both be upgraded to receive the runtime fixes.
The managed upgrade preserves durable homes, browser profiles, computer settings,
and each computer's running/stopped state. This release does not introduce a
state-format migration or enable additional network exposure.

Refresh Open WebUI's cached tool catalog after upgrading. MCP and generic
OpenAPI retain their existing tool names and parameters. Existing compatibility
endpoint aliases and native `POST /execute` remain available; the model catalog
uses one command-start operation to make refresh behavior consistent.

A shared Open WebUI connection still uses one Qubicl computer. Chat-specific
folder tracking is not user or filesystem isolation. Use separate computers
and connection grants where isolation is required.

## Preview and search limits

Office PDF previews require `workstation`. Both input and output are limited to
20 MB, conversion has a 30-second deadline, and at most two conversions run at
once. Font availability and document features can affect rendering fidelity.

Content search retains its 500-attempt / 25 MB read budget and 1 MiB per-file
limit. Traversal, ignore-file loading, and result storage are bounded; incomplete
results are marked `truncated`. Continuation snapshots expire after 15 seconds;
start at offset zero to refresh after external file changes. Git global excludes
and ancestor ignore rules above the selected search root are not applied.

Published HTTP apps must use relative assets/redirects or a configured public
proxy base path. Qubicl does not rewrite root URLs or forward operator cookies,
and app cookie sessions are unsupported. The isolated published preview route
supports WebSockets; the native Open Terminal proxy does not. PTYs, notebooks,
and automatic per-chat computer provisioning remain outside this release.

## Release evidence

The pre-1.0 `initial` release profile requires a complete scanned candidate and
signed schema-4 post-freeze client, protocol, lifecycle, and native-Linux remote
acceptance records. Published evidence identifies the exact validated artifacts
and platforms. Broader cross-platform support is not inferred from focused
source tests or from the existence of multi-architecture images.
