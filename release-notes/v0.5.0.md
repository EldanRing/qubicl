# Qubicl 0.5.0

Qubicl 0.5.0 adds a local management dashboard backed by a native host helper,
and hardens lifecycle, backup, upgrade, process, preview, and recovery behavior.
The CLI remains the source of truth and all management stays on hardware you
control.

## Highlights

- A responsive light/dark dashboard manages setup, computers, resources,
  lifecycle, updates, tools, skills, network policy, scoped credentials,
  backups, diagnostics, operations, settings, and sessions. It shows bounded
  process/controller metadata without exposing commands, working directories,
  output, file contents, bearer tokens, or credential values.
- The native helper can run in the foreground or as a login-time systemd user
  service on Linux x64 and LaunchAgent on Apple Silicon macOS. A protected local
  recovery page remains available when Docker or the dashboard container is not.
- Optional remote administration uses direct private HTTPS with an exact
  administrator hostname, private-interface/client-network policy, strict
  certificate and key checks, and an origin separate from agent, viewer, and
  workload-preview traffic. It does not create public access, DNS, certificates,
  tunnels, router rules, or firewall rules.
- Management changes use expiring, session-bound plans with final state,
  runtime, and journal checks. Sensitive changes require password
  reauthentication, and retained credential inputs are scrubbed after expiry,
  stale rejection, or completion.
- Manual dashboard backups support verified stopped or temporarily quiesced
  captures, restore to a new computer, and exact retention previews. Lifecycle,
  backup, migration, and upgrade journals now recover only matching immutable
  runtime identities and preserve ambiguous states for review.
- Candidate tooling now covers the isolated dashboard image and its exact asset
  manifest alongside the gateway and four computer presets on amd64 and arm64.

## Upgrade and compatibility

Install the matching CLI, review the state migration, then review the coordinated
runtime upgrade:

```sh
npm install -g qubicl-cli@0.5.0
qubicl setup
qubicl upgrade --all
```

Existing installations use a new state-format boundary. Moving to state format
4 requires explicit confirmation and creates a protected checksummed copy of
the prior state. The migration preserves computer identities, tokens, homes,
trash, resources, policies, image identities, and existing running/stopped
intent; it does not start containers. Back up the complete Qubicl state root and
durable homes before upgrading.

Older CLIs refuse state format 4. Downgrading therefore requires restoring the
complete protected pre-migration state with a compatible CLI; restoring only a
computer home is insufficient. Dashboard data uses its own schema 1 and the
embedded image catalog uses schema 2.

The gateway and curated computer images must be upgraded to receive the runtime
and recovery changes. `upgrade --all` preserves durable homes, browser profiles,
computer configuration, and running/stopped intent while replacing verified
disposable runtime components. Existing client tool names and MCP, OpenAPI,
Open Terminal, and Open WebUI connection methods remain available. Refresh any
client that caches tool discovery after upgrading.

Fresh core skill working copies now compare against the reviewed catalog with
the same deterministic path ordering, so nested document skills start with an
`unchanged` integrity status and real local edits remain visible.

## Security changes

The host helper holds management authority and is the only dashboard component
that can reach protected state or Docker. The dashboard container serves static
catalog-bound assets through a loopback-only port on a dedicated ordinary bridge.
That bridge gives the static sidecar ordinary container egress, but the sidecar
receives no Docker socket, host mounts, administrator password, cookies,
credentials, or TLS private keys.

Passwords use bounded asynchronous scrypt. Local sessions keep their bearer
only in browser memory; remote sessions use Secure, HttpOnly cookies. Both paths
enforce CSRF, exact Host and Origin policy, idle and absolute expiry, rotation on
reauthentication, rate limits, and listener-wide revocation. Remote certificates
must contain exactly the administrator DNS identity; extra DNS, IP, URI, or
email identities are rejected.

Operation plans bind the current state, runtime, journal, authenticated session,
and reviewed effects. The helper serializes mutations, records durable receipts,
and never replays arbitrary requests after interruption. Preview and viewer
handoffs use bounded tickets and isolated origins.

The locked Hono runtime is updated to 4.13.7, resolving its current path
traversal, nested-form denial-of-service, and URL-fragment parsing advisories.

## Known limitations

- Dashboard services are supported on native Linux x64 and Apple Silicon macOS.
  Windows/WSL dashboard service installation, Linux ARM64, Intel macOS,
  pre-login Linux operation, and native Windows remain outside this release.
- Remote administration is private-network HTTPS only. You provide trusted DNS,
  certificate lifecycle, routing, and firewall policy. Gateway TLS remains a
  separate configuration for remote agent, viewer, and workload-preview access.
- Dashboard backups are manual, home-only, and unencrypted. They may contain
  browser cookies, logged-in sessions, credentials, and personal files.
  Encrypted backups remain CLI-only; scheduled backups and a complete-install
  export are not included.
- The dashboard is one-owner administration rather than multi-user RBAC. A
  shared Qubicl computer or Open Terminal connection does not isolate users or
  chat folders from one another.
- Qubicl is intended for trusted or operator-supervised workloads. A computer
  container is not a VM boundary for deliberately hostile code.

signed release-set and schema-4 acceptance records, all nine named clients and
four protocol profiles, native Linux systemd and Apple Silicon LaunchAgent
dashboard service/TLS/reboot evidence, and physical iPhone Safari dashboard
evidence. Published evidence identifies the exact tested artifacts, versions,
platforms, and retained checks. Focused source or simulated browser tests do not
stand in for those release runs.
